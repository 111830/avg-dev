# Notes: C++ Modules and Compilation Process (C++23)

## 1. File Structure Rules (.cppm)

The most important rule in C++20/23 when creating modules is ordering. There are two correct ways, depending on which libraries you're using.

### A. Modern Way (Only `import`)
If you're using modern libraries (modules), the module declaration comes first.

```cpp
export module airline_ticket;  // <--- First line!

import <iostream>;             // Imports come AFTER declaration
import <string>;

export class AirlineTicket {
    // ... code
};
```

### B. "Hybrid" Way (When you need `module;` and `#include`)
If you're forced to use old libraries with `#include` (that haven't been converted to modules yet), you must start with `module;`.

**Rule:** Inside the `module; ... export module` section, `import` is NOT allowed, only `#include` and preprocessor directives.

```cpp
module;                        // 1. Space for old code (Global Module Fragment)

#include <cstdio>              // 2. Only #include allowed here (not import)
#include <vector>

export module airline_ticket;  // 3. Your actual module starts here

import <iostream>;             // 4. Modern imports start here
import <string>;

export class AirlineTicket {
   // ...
};
```

### C. WRONG (Import before Module)
You cannot do `import` before telling the compiler that this file is a module.

```cpp
import <iostream>;             // WRONG: This is not allowed here
export module airline_ticket;  // WRONG: This should have been at the top
```

## 2. Why does this happen? (Technical Reasoning)

The reason the ordering is strict relates to how the compiler (GCC/Clang) works:

1. **`module;` (Global Module Fragment):** Tells the compiler: "Wait, I have some old C++ headers to copy with `#include` before entering the module world." You cannot do `import` here because we're not yet in the "module world".

2. **`export module ...`:** This is the gateway. After this line, we're inside the module and can use `import`.

3. **Difference `import` vs `#include`:**
   - `import`: Much faster and isolated.
   - `#include`: Simply slow textual copy-paste.

## 3. Terminal Commands (Cheat Sheet)

To work with C++23 Modules in GCC, follow these exact steps:

### Step 1: "Preparing" System Libraries (Done only once)
Before we can use `import <iostream>`, we need to convert it to binary format (.gcm).

```bash
g++ -std=c++23 -fmodules-ts -x c++-system-header iostream
g++ -std=c++23 -fmodules-ts -x c++-system-header string
# g++ -std=c++23 -fmodules-ts -x c++-system-header print (Optional, if supported)
```

### Step 2: Compiling Your Module (.cppm)
This creates the object file (`.o`) and registers the module in cache.

- `-x c++`: Tells it that it's a C++ file (even though it has .cppm extension).
- `-c`: Only compile, don't link.

```bash
g++ -std=c++23 -fmodules-ts -x c++ -c airline_ticket.cppm
```

### Step 3: Compiling Main and Linking
Combines `main.cpp` with the compiled module (`airline_ticket.o`).

```bash
g++ -std=c++23 -fmodules-ts main.cpp airline_ticket.o -o ticket_evaluation
```

### Step 4: Execution

```bash
./ticket_evaluation
```

## Quick Summary

| Step | Command | Purpose |
|------|---------|---------|
| 1 | `g++ -std=c++23 -fmodules-ts -x c++-system-header iostream` | Prepare system libraries |
| 2 | `g++ -std=c++23 -fmodules-ts -x c++ -c module.cppm` | Compile the module |
| 3 | `g++ -std=c++23 -fmodules-ts main.cpp module.o -o program` | Link and create executable |
| 4 | `./program` | Execute the program |

**Note:** The module must follow the correct structure (A or B) according to project needs.
